# Linux TUI: portable ProxMenux equivalent

Working name: **Linux TUI**. Research baseline: MacRimi/ProxMenux commit
`7215c551d402370408b1c7a70c1833066af046a2`, reviewed October 10, 2026.

## Product boundary

Install and run inside Linux VMs, LXC containers and bare-metal Linux independently of the hypervisor. A VM on Proxmox remains a supported Linux guest; the application does not communicate with Proxmox. Local operations are the default. Optional SSH targets and Linux-native host providers extend management later.

Preserve portable feature intent, not assumptions about root, Debian, systemd, physical hardware or host access. Show unavailable features with the reason. A container cannot configure its host's kernel, pass through a GPU, create a VM, change its UID map or read physical SMART data merely because root is available inside the container. Nested virtualization is an explicitly detected capability.

This is a staged implementation. The inventory is a coverage baseline, not a claim that every listed feature is implemented. External community scripts need separate review; their content is not captured by cloning this repository.

## Explicit exclusions

Remove Proxmox APIs, credentials, cluster/node discovery, `/etc/pve`, `qm`, `pct`, `pvesh`, `pveum`, PVE-specific metrics/configuration, guest orchestration through PVE, subscription banner removal, enterprise/no-subscription/Ceph repository manipulation, PVE appliance-manager updates, PVE 8-to-9 migration/checks and version-specific upgrade/repair scripts. Remove PVE HA/Corosync/cluster restore, `vzdump` tuning/jobs/hooks/retention inheritance, PVE replication events and PBS client/destination/encryption recovery integration. Do not replace these with another mandatory control plane.

Ceph is not inherently Proxmox-only: retain generic monitoring when present and leave general cluster administration as an optional future provider. Likewise retain generic kernel/driver restore while dropping PVE kernel-selection rules. Keep disk/GPU/VM/container intent through independent host providers. Exclude OSX-PROXMOX and Proxmox VE Helper Scripts execution; portable app functionality can become separately reviewed recipes. Proprietary NAS/community installers and UUP Dump links are catalog/reference entries until independently verified.

## Coverage method and limits

`research/upstream-inventory.json` records every tracked upstream file with size and SHA-256 plus line-level function/class, route, translated UI and Proxmox-coupling evidence. `upstream-files.md` is the browsable path inventory; `upstream-api-checklist.md` captures route declarations for individual review. This preserves mixed modules for review rather than discarding entire files based on a keyword. The static extractor does not discover every dynamic action, dependency or external script. Functional parity requires action-level acceptance tests and Linux environment validation, not matching file counts.

Specific notification channel targets found in source: Telegram, Gotify, Pushover, Discord, email and Apprise. AI provider modules include OpenAI, Anthropic, Gemini, Groq, Ollama and OpenRouter; retain provider configuration and enrichment as optional functionality. Preserve authenticated web terminal/session and script progress functionality through the administrative broker, with bounded session lifecycle and permission checks. Preserve backup encryption/recovery intent for generic destinations while excluding PBS-specific implementation. Browser documentation (`web/`) is a separate Next.js project from the actual monitor (`AppImage/`); both are inventoried.
